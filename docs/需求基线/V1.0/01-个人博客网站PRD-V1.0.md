## 02 产品概述

### 2.1 产品背景

个人网站是博主展示个人信息、分享知识和记录日常动态的载体。

本项目计划建设一个以博主个人展示和内容分享为核心的网站，既提供面向公众的内容浏览能力，也允许注册用户发布自己的动态。

网站需要兼顾内容阅读体验、个人动态管理、账号安全及后台内容管理能力。

### 2.2 产品定位

本产品定位为一个支持多角色访问的博主个人网站，主要包含三个公共模块：

- **首页：** 展示博主个人介绍、内容统计、网站运行时间和社交链接。
- **随记：** 博主发布的知识分享、文章和个人笔记，所有人均可阅读。
- **片刻：** 类似轻量动态空间，注册用户可以发布文字和图片，并设置公开或私密。

网站同时提供个人中心和管理员后台。

### 2.3 目标用户

| 用户类型 | 用户描述          | 核心需求                 |
| ---- | ------------- | -------------------- |
| 访客   | 未登录的浏览者       | 了解博主、阅读随记、浏览公开片刻     |
| 普通用户 | 已注册并完成邮箱验证的用户 | 管理个人资料，发布和管理自己的片刻    |
| 管理员  | 博主本人          | 管理随记、标签、所有片刻、用户及首页配置 |

### 2.4 用户痛点

1. 缺少统一展示个人信息、知识内容和日常记录的空间。
2. 传统文章博客不便于记录短小、随性的动态。
3. 用户发布的个人动态需要支持公开分享与私密记录。
4. 博主需要便捷地维护内容、标签和网站展示信息。
5. 私密内容及用户数据需要明确的权限和安全保护机制。

### 2.5 产品目标

- 建立统一的个人展示与内容分享平台。
- 提供便捷的随记阅读、搜索和标签筛选能力。
- 支持注册用户独立管理自己的公开和私密片刻。
- 为博主提供完整的内容与用户管理能力。
- 确保私密内容访问、账号安全和删除行为符合预期。
- 为后续扩展功能保留合理的设计空间。

## 03 产品范围

### 3.1 本期建设范围

| 模块   | 建设内容                          |
| ---- | ----------------------------- |
| 首页   | 个人介绍、随记数量、标签统计、网站运行时间、社交链接    |
| 随记   | 列表、详情弹窗、Markdown、搜索、标签筛选、分页   |
| 随记管理 | 随记新增、编辑、删除                    |
| 标签管理 | 标签新增、编辑、删除及随记关联管理             |
| 片刻   | 发布、编辑、删除、公开/私密设置、搜索、分页        |
| 用户认证 | 注册、登录、邮箱验证、找回密码、退出登录          |
| 个人中心 | 修改昵称、头像、简介、邮箱和密码；管理我的片刻       |
| 用户管理 | 用户列表、禁用、启用、删除                 |
| 管理后台 | 管理随记、标签、全部片刻、用户和首页配置          |
| 安全机制 | 服务端权限校验、验证码限制、登录失败限制、账号状态控制   |
| 图片展示 | 通过 URL 引用封面、头像及 Markdown 正文图片 |

### 3.2 不包含的功能

第一版不包含：

- 片刻点赞、评论。
- 用户关注、私信等社交功能。
- 随记分类体系。
- 本地图片上传、图片文件托管及图片管理服务。
- 片刻草稿。
- 普通用户自行申请管理员角色。
- 第三方账号登录。
- 复杂内容推荐、个性化信息流。
- 原生移动端 App。

### 3.3 版本规划

| 版本   | 范围                 | 状态     |
| ---- | ------------------ | ------ |
| V1.0 | 完成本文档中确定的核心功能      | 本期建设目标 |
| V1.x | 根据实际使用反馈完善体验、修复问题  | 待规划    |
| V2.0 | 根据后续需求评估评论、互动等扩展能力 | 暂不纳入本期 |

后续版本仅作为规划方向，不代表已承诺开发。

### 3.4 项目约束

1. 技术栈暂不确定，后续根据需求和技术评估决定。
2. 图片通过外部 URL 引用，第一版不提供本地上传。
3. 随记仅由管理员管理，普通用户不得创建或修改随记。
4. 普通用户只能管理自己的片刻，管理员可以管理所有用户的片刻。
5. 私密片刻必须执行严格的服务端访问控制。
6. 产品需求不直接规定数据库表结构、具体 API 设计或技术实现细节。

## 04 用户角色与权限

### 4.1 用户角色定义

**访客：** 未登录用户，只能访问公开内容和公共页面。

**普通用户：** 完成注册、邮箱验证并登录的用户，可以维护个人资料及管理自己的片刻。

**管理员：** 博主本人，账号由预先创建的管理流程提供，拥有全站内容及用户管理权限。

### 4.2 角色权限矩阵

| 功能         | 访客    | 普通用户         | 管理员  |
| ---------- | ----- | ------------ | ---- |
| 浏览首页       | 允许    | 允许           | 允许   |
| 浏览随记       | 允许    | 允许           | 允许   |
| 搜索、筛选随记    | 允许    | 允许           | 允许   |
| 管理随记和标签    | 禁止    | 禁止           | 允许   |
| 浏览公开片刻     | 允许    | 允许           | 允许   |
| 浏览自己的私密片刻  | 禁止    | 允许           | 允许   |
| 浏览他人的私密片刻  | 禁止    | 禁止           | 允许   |
| 发布片刻       | 禁止    | 允许           | 允许   |
| 编辑、删除自己的片刻 | 禁止    | 允许           | 允许   |
| 编辑、删除他人的片刻 | 禁止    | 禁止           | 允许   |
| 修改片刻可见性    | 禁止    | 仅自己的片刻       | 所有片刻 |
| 搜索片刻       | 仅公开内容 | 公开内容及自己的私密内容 | 所有片刻 |
| 修改个人资料     | 禁止    | 允许           | 允许   |
| 查看和管理用户    | 禁止    | 禁止           | 允许   |
| 修改首页配置     | 禁止    | 禁止           | 允许   |

### 4.3 权限规则

1. 所有受保护操作必须由服务端执行权限校验。
2. 普通用户不得通过修改请求参数、直接访问管理页面或调用接口获得管理员权限。
3. 管理员编辑其他用户的片刻时，不允许修改发布者身份。
4. 私密片刻的权限限制必须覆盖列表、搜索、详情、分页及相关资源访问。
5. 用户被禁用后不能登录，已有登录凭证失效。
6. 管理员删除用户时，公开片刻保留并匿名展示，私密片刻永久删除。

## 05 功能需求

本章以用户故事为主要组织单位。每个用户故事包含对应的功能要求、业务规则和验收标准。

编号规则如下：

- `FR`：功能需求。
- `US`：用户故事。
- `AC`：验收标准。

层级关系如下：

```text
功能模块
└── 用户故事（US）
    ├── 功能要求（FR）
    ├── 业务规则
    └── 验收标准（AC）
```

用户故事采用“作为某类用户，我希望……以便……”的格式。FR 描述系统为实现用户故事必须提供的功能，业务规则定义功能约束，AC 用于判断用户故事是否完成。

### 5.1 首页

#### US-HOME-001：展示个人介绍

**用户故事：** 作为访客，我希望在首页看到博主的昵称、头像和个人简介，以便快速了解博主。

##### 功能要求

- **FR-HOME-001：** 展示个人介绍。

##### 业务规则

- 个人介绍由管理员在后台维护。
- 首页自动展示最新保存的信息。
- 普通用户不能修改博主的首页个人介绍。

##### 验收标准（AC）

- AC-HOME-001-01：打开首页时，能够展示已配置的昵称、头像和简介。
- AC-HOME-001-02：管理员修改个人介绍后，首页展示更新后的内容。
- AC-HOME-001-03：普通用户不能修改博主的首页个人介绍。

#### US-HOME-002：随记数量和标签统计

**用户故事：** 作为访客，我希望查看随记数量和标签统计，以便了解博主分享的内容规模及主题。

##### 功能要求

- **FR-HOME-002：** 随记数量和标签统计。

##### 业务规则

- 随记数量根据实际随记数据自动计算。
- 标签统计根据随记与标签的关联数据计算。
- 不设置随记分类体系。
- 新增、删除随记或修改标签关联后，统计数据相应更新。

##### 验收标准（AC）

- AC-HOME-002-01：首页显示的随记数量与实际随记数据一致。
- AC-HOME-002-02：标签统计能够反映实际标签关联情况。
- AC-HOME-002-03：数据变化后，不需要管理员手动修改统计数字。

#### US-HOME-003：网站运行时间

**用户故事：** 作为访客，我希望看到网站运行时间，以便了解网站的建立时间。

##### 功能要求

- **FR-HOME-003：** 网站运行时间。

##### 业务规则

- 管理员可以配置网站创建日期。
- 运行时间根据当前日期和创建日期计算。
- 修改创建日期后，运行时间重新计算。

##### 验收标准（AC）

- AC-HOME-003-01：系统根据配置的创建日期计算运行时间。
- AC-HOME-003-02：管理员修改创建日期后，展示结果相应变化。

具体显示格式待 UI 设计阶段确定。

#### US-HOME-004：社交链接

**用户故事：** 作为访客，我希望通过首页访问博主的社交平台，以便了解博主的其他内容。

##### 功能要求

- **FR-HOME-004：** 社交链接。

##### 业务规则

- 管理员可以新增、编辑、删除社交链接。
- 每条链接包含名称、图标、URL 和显示顺序。
- 首页自动展示已配置的链接。

##### 验收标准（AC）

- AC-HOME-004-01：管理员可以维护社交链接。
- AC-HOME-004-02：首页按照配置展示链接。
- AC-HOME-004-03：访问链接时跳转到配置的目标地址。

### 5.2 随记模块

#### US-NOTE-001：随记列表和分页

**用户故事：** 作为访客，我希望浏览随记列表，以便发现感兴趣的文章。

##### 功能要求

- **FR-NOTE-001：** 随记列表和分页。

##### 业务规则

- 随记按创建时间倒序排列。
- 每页显示 10 条。
- 列表展示标题、摘要、封面图（存在时）及标签。
- 没有数据时显示空状态。

##### 验收标准（AC）

- AC-NOTE-001-01：随记列表按照创建时间倒序排列。
- AC-NOTE-001-02：每页最多展示 10 条随记。
- AC-NOTE-001-03：用户可以切换上一页、下一页。
- AC-NOTE-001-04：无数据时显示明确的空状态。

#### US-NOTE-002：阅读随记

**用户故事：** 作为访客，我希望通过弹窗阅读随记，以便在不离开列表的情况下查看内容。

##### 功能要求

- **FR-NOTE-002：** 阅读随记。

##### 业务规则

- 点击随记后打开阅读弹窗，不跳转到独立阅读页面。
- 正文使用 Markdown 渲染。
- 支持标题目录、代码高亮、代码复制和正文图片展示。

##### 验收标准（AC）

- AC-NOTE-002-01：点击随记后打开弹窗并展示正文。
- AC-NOTE-002-02：Markdown 标题能够生成对应的目录。
- AC-NOTE-002-03：代码能够进行语法高亮并支持复制。
- AC-NOTE-002-04：正文中的有效图片 URL 能够正常展示。
- AC-NOTE-002-05：关闭弹窗后，用户可以继续浏览原列表。

#### US-NOTE-003：随记新增、编辑和删除

**用户故事：** 作为管理员，我希望管理随记，以便持续维护博客内容。

##### 功能要求

- **FR-NOTE-003：** 随记新增、编辑和删除。

随记字段：

- 标题
- 摘要
- 封面图 URL（可选）
- Markdown 正文
- 标签关联

##### 业务规则

- 仅管理员可以新增、编辑和删除随记。
- 删除前必须二次确认。
- 确认后永久删除随记。

##### 验收标准（AC）

- AC-NOTE-003-01：管理员可以新增和编辑随记。
- AC-NOTE-003-02：保存后的内容能够在随记列表和阅读弹窗中正确展示。
- AC-NOTE-003-03：访客和普通用户不能新增、编辑或删除随记。
- AC-NOTE-003-04：删除随记前显示确认提示。
- AC-NOTE-003-05：确认删除后，随记不再出现在列表、搜索和阅读结果中。

#### US-NOTE-004：标签管理

**用户故事：** 作为管理员，我希望维护标签，以便对随记进行主题整理。

##### 功能要求

- **FR-NOTE-004：** 标签管理。

##### 业务规则

- 一篇随记可以关联多个标签。
- 一个标签可以关联多篇随记。
- 编辑标签名称后，所有关联随记显示新名称。
- 删除标签只解除标签关联，不删除随记。
- 删除正在使用的标签时显示确认提示。

##### 验收标准（AC）

- AC-NOTE-004-01：管理员可以新增、编辑和删除标签。
- AC-NOTE-004-02：修改标签名称后，关联随记展示新名称。
- AC-NOTE-004-03：删除标签后，关联随记仍然存在。
- AC-NOTE-004-04：删除标签后，相关随记不再通过该标签筛选出来。
- AC-NOTE-004-05：访客和普通用户不能管理标签。

#### US-NOTE-005：随记搜索和标签筛选

**用户故事：** 作为访客，我希望搜索随记并按标签筛选，以便快速找到相关内容。

##### 功能要求

- **FR-NOTE-005：** 随记搜索和标签筛选。

##### 业务规则

- 关键词搜索范围包括标题、摘要和正文。
- 支持按标签筛选。
- 关键词搜索与标签筛选可以组合使用。
- 搜索和筛选结果采用分页。
- 无匹配结果时提供清晰提示和清除条件的操作。

##### 验收标准（AC）

- AC-NOTE-005-01：输入关键词后，返回匹配标题、摘要或正文的随记。
- AC-NOTE-005-02：选择标签后，只返回符合标签条件的随记。
- AC-NOTE-005-03：同时使用关键词和标签时，结果同时满足两项条件。
- AC-NOTE-005-04：无结果时显示空状态，并允许清除搜索条件。

#### US-NOTE-006：随记图片 URL

**用户故事：** 作为管理员，我希望使用图片 URL 配置封面和正文图片，以便在不建设图片上传服务的情况下展示图片。

##### 功能要求

- **FR-NOTE-006：** 随记图片 URL。

##### 业务规则

- 封面图通过独立 URL 字段配置。
- 正文图片使用 Markdown 图片语法。
- 仅允许 HTTP 和 HTTPS 协议。
- 保存时检查格式，不主动请求每个图片地址验证其实际可访问性。
- 图片加载失败时显示友好占位提示。

##### 验收标准（AC）

- AC-NOTE-006-01：管理员可以配置有效格式的封面图 URL。
- AC-NOTE-006-02：正文支持 Markdown 图片。
- AC-NOTE-006-03：不符合允许协议的图片 URL 被拒绝。
- AC-NOTE-006-04：图片无法加载时，正文其他内容仍可正常阅读。
- AC-NOTE-006-05：系统不提供本地图片上传功能。

### 5.3 片刻模块

#### US-MOMENT-001：浏览片刻

**用户故事：** 作为访客，我希望浏览公开片刻，以便了解博主及用户分享的动态。

##### 功能要求

- **FR-MOMENT-001：** 浏览片刻。

##### 业务规则

- 片刻按创建时间倒序排列。
- 每页显示 10 条。
- 正文使用 Markdown 渲染。
- 支持文字、单张图片和多张图片。
- 正文可以为空，但正文和图片至少有一项有效内容。

##### 验收标准（AC）

- AC-MOMENT-001-01：访客可以浏览公开片刻。
- AC-MOMENT-001-02：私密片刻不向访客展示。
- AC-MOMENT-001-03：列表按创建时间倒序排列，每页最多展示 10 条。
- AC-MOMENT-001-04：文字和图片能够按照 Markdown 内容正确渲染。
- AC-MOMENT-001-05：空白正文且没有图片的片刻不能成功发布。

#### US-MOMENT-002：发布片刻

**用户故事：** 作为普通用户，我希望发布文字或图片动态，以便记录和分享日常内容。

##### 功能要求

##### 业务规则

- 可以选择公开或私密。
- 支持纯文字、文字加图片、纯图片动态。
- 图片通过 Markdown 图片语法引用 URL。

##### 验收标准（AC）

- AC-MOMENT-002-01：登录用户可以成功发布有效片刻。
- AC-MOMENT-002-02：用户可以选择公开或私密。
- AC-MOMENT-002-03：正文为空但包含有效图片时，允许发布。
- AC-MOMENT-002-04：正文和图片均无有效内容时，拒绝发布。
- AC-MOMENT-002-05：访客不能发布片刻。

#### US-MOMENT-003：编辑片刻

**用户故事：** 作为普通用户，我希望编辑自己的片刻，以便修正或更新已发布内容。

##### 验收标准（AC）

- AC-MOMENT-003-02：普通用户不能编辑他人的片刻。
- AC-MOMENT-003-03：管理员可以编辑所有用户的片刻。
- AC-MOMENT-003-04：编辑操作不能修改发布者身份。
- AC-MOMENT-003-05：编辑旧片刻后，其列表顺序仍按原始创建时间确定。

#### US-MOMENT-004：删除片刻

**用户故事：** 作为片刻发布者，我希望删除自己的片刻，以便移除不再需要的内容。

##### 功能要求

- **FR-MOMENT-004：** 删除片刻。

##### 业务规则

- 普通用户只能删除自己的片刻。
- 管理员可以删除任意用户的片刻。
- 删除前进行二次确认。
- 确认后永久删除，不提供恢复功能。

##### 验收标准（AC）

- AC-MOMENT-004-01：删除前显示二次确认提示。
- AC-MOMENT-004-02：取消确认时不执行删除。
- AC-MOMENT-004-03：确认删除后，该片刻不再出现在列表、搜索和详情结果中。
- AC-MOMENT-004-04：普通用户不能删除他人的片刻。

#### US-MOMENT-005：公开和私密设置

**用户故事：** 作为普通用户，我希望将自己的片刻设置为公开或私密，以便控制内容的可见范围。

##### 功能要求

- **FR-MOMENT-005：** 公开和私密设置。

##### 业务规则

- 私密片刻仅发布者本人和管理员可见。
- 普通用户只能修改自己的片刻可见性。
- 管理员可以修改所有片刻可见性。

##### 验收标准（AC）

- AC-MOMENT-005-02：普通用户不能查看其他用户的私密片刻。
- AC-MOMENT-005-03：将公开片刻改为私密后，无权用户无法通过历史 URL、搜索或接口继续访问。
- AC-MOMENT-005-04：管理员能够查看和管理所有片刻。

#### US-MOMENT-006：片刻搜索

##### 功能要求

- **FR-MOMENT-006：** 片刻搜索。

- 搜索范围为 Markdown 正文。
- 访客只能搜索公开片刻。
- 普通用户可以搜索公开片刻及自己的私密片刻。
- 管理员可以搜索所有片刻。

##### 验收标准（AC）

- AC-MOMENT-006-01：访客搜索结果只包含公开片刻。
- AC-MOMENT-006-02：普通用户可以搜索自己的私密片刻。
- AC-MOMENT-006-03：普通用户不能通过搜索获得他人的私密片刻。

#### US-MOMENT-007：图片 URL 校验

### 5.4 注册、登录与账号安全

#### US-AUTH-001：注册与邮箱验证

**用户故事：** 作为访客，我希望注册并验证邮箱，以便创建自己的账号并使用片刻功能。

##### 功能要求

- **FR-AUTH-001：** 注册与邮箱验证。

##### 业务规则

- 注册字段为昵称、邮箱、密码。
- 同一个邮箱只能注册一个账号。
- 注册后必须完成邮箱验证才能正常使用账号。
- 公开注册只能创建普通用户。
- 验证码具有有效期、错误次数限制和重新发送间隔。
- 邮件发送失败时，系统提示重试，不开放未验证账号的正常使用权限。

##### 验收标准（AC）

- AC-AUTH-001-01：注册时必须提供昵称、邮箱和密码。
- AC-AUTH-001-02：重复邮箱注册被拒绝。
- AC-AUTH-001-03：邮箱验证成功后，账号获得正常使用资格。
- AC-AUTH-001-04：验证码过期或错误次数超限时，系统拒绝验证。
- AC-AUTH-001-05：普通用户无法通过公开注册获得管理员权限。

#### US-AUTH-002：登录与退出登录

**用户故事：** 作为注册用户，我希望登录并保持登录状态，以便访问个人中心和管理自己的片刻。

##### 业务规则

- 登录成功后保持有效登录状态。
- 用户退出登录后，当前登录状态失效。
- 连续登录失败达到限制时，临时限制继续尝试。
- 被禁用账号不能登录，已有登录凭证失效。

##### 验收标准（AC）

- AC-AUTH-002-01：有效账号凭证能够完成登录。
- AC-AUTH-002-02：退出登录后，受保护操作不能继续使用原登录状态。
- AC-AUTH-002-03：被禁用账号不能登录。
- AC-AUTH-002-04：连续登录失败达到限制时，系统执行临时防护。

#### US-AUTH-003：找回密码

**用户故事：** 作为忘记密码的用户，我希望通过邮箱验证码重置密码，以便恢复账号使用能力。

##### 功能要求

- **FR-AUTH-003：** 找回密码。

##### 业务规则

- 通过邮箱验证码完成密码重置。
- 验证码必须有效。
- 重置成功后，新密码生效，旧密码失效。

##### 验收标准（AC）

- AC-AUTH-003-01：有效验证码可以完成密码重置。
- AC-AUTH-003-02：过期或错误验证码不能完成密码重置。
- AC-AUTH-003-03：重置成功后，旧密码不能继续登录。

#### US-AUTH-004：修改密码

**用户故事：** 作为登录用户，我希望修改密码，以便保护账号安全。

##### 功能要求

- **FR-AUTH-004：** 修改密码。

##### 业务规则

- 登录用户可以修改自己的密码。
- 修改成功后，其他登录会话失效。

##### 验收标准（AC）

- AC-AUTH-004-01：用户能够修改自己的密码。
- AC-AUTH-004-02：修改成功后，旧密码失效。
- AC-AUTH-004-03：账号其他登录会话失效，需要重新认证。

#### US-AUTH-005：修改邮箱

**用户故事：** 作为登录用户，我希望修改绑定邮箱，以便维护正确的联系方式。

##### 功能要求

- **FR-AUTH-005：** 修改邮箱。

##### 业务规则

##### 验收标准（AC）

- AC-AUTH-005-02：新邮箱验证成功后，系统更新绑定邮箱。
- AC-AUTH-005-03：新邮箱与其他账号冲突时，系统拒绝修改。

## 06 数据与内容规则

本章定义业务数据的保存、可见性和生命周期，不涉及具体数据库表设计。

### 6.1 需要保存的数据

| 数据类别   | 主要业务信息                              |
| ------ | ----------------------------------- |
| 用户账号   | 昵称、邮箱、密码哈希、账号角色、账号状态                |
| 用户资料   | 头像 URL、个人简介                         |
| 随记     | 标题、摘要、封面图 URL、Markdown 正文、创建时间及更新时间 |
| 标签     | 标签名称及与随记的关联关系                       |
| 片刻     | 发布者、Markdown 正文、可见性、创建时间及更新时间       |
| 网站配置   | 网站创建日期、博主个人介绍                       |
| 社交链接   | 链接名称、图标、URL、显示顺序                    |
| 验证相关数据 | 邮箱验证码及其有效期、错误次数和发送限制所需信息            |

密码不得以明文形式保存。验证码等敏感数据的具体存储方式由技术设计阶段确定。

### 6.2 数据可见性

| 数据      | 访客   | 普通用户 | 管理员 |
| ------- | ---- | ---- | --- |
| 博主公开资料  | 可见   | 可见   | 可见  |
| 随记      | 可见   | 可见   | 可见  |
| 公开片刻    | 可见   | 可见   | 可见  |
| 自己的私密片刻 | 不可访问 | 可见   | 可见  |
| 他人的私密片刻 | 不可访问 | 不可访问 | 可见  |
| 用户管理信息  | 不可访问 | 不可访问 | 可访问 |

具体个人资料的公开展示字段可在后续规格说明书中明确。

### 6.3 数据生命周期

#### 用户账号

用户注册后处于待验证状态，完成邮箱验证后进入正常状态。

管理员禁用用户后，账号不能登录，但历史内容按照禁用规则保留。

管理员删除用户后，账号不再允许登录，并执行相应内容保留和删除规则。

#### 随记

随记由管理员创建、编辑和删除。

随记删除后永久删除，不提供恢复功能。

删除标签只解除标签与随记的关联，不删除随记本身。

#### 片刻

片刻创建后，可以被发布者或管理员编辑。

编辑不改变原始创建时间，也不能改变发布者身份。

删除片刻后永久删除，不提供恢复功能。

#### 社交链接和网站配置

管理员可以新增、修改和删除配置。

配置修改后，首页使用最新有效配置进行展示。

### 6.4 删除与保留规则

| 操作        | 处理规则                 |
| --------- | -------------------- |
| 删除随记      | 永久删除随记               |
| 删除标签      | 删除标签及其关联关系，保留随记      |
| 删除用户自己的片刻 | 永久删除该片刻              |
| 管理员删除任意片刻 | 永久删除该片刻              |
| 禁用用户      | 保留所有历史片刻；私密片刻仅管理员可查看 |
| 重新启用用户    | 恢复账号使用资格，不恢复已删除的数据   |
| 删除用户      | 公开片刻保留并匿名展示；私密片刻永久删除 |
| 删除最后一个管理员 | 禁止操作                 |

### 6.5 图片与外部资源规则

- 第一版不保存用户上传的图片文件。
- 头像、封面图和 Markdown 图片通过 URL 引用。
- 仅允许 HTTP 和 HTTPS 协议。
- 系统不保证外部图片 URL 长期有效。
- 外部图片加载失败不应导致整条内容无法阅读。
- 图片 URL 不得绕过对应内容的访问权限。私密内容中的图片引用不得通过系统接口向无权用户泄露。

## 07 非功能需求

### 7.1 性能

- 随记和片刻列表必须分页。
- 默认每页展示 10 条记录。
- 搜索和标签筛选应在合理时间内返回结果。
- 首页统计应基于真实数据，避免依赖手动维护的数字。
- 具体响应时间指标及目标数据规模待技术设计阶段确定。

### 7.2 安全性

- 密码使用安全的密码哈希算法存储。
- 服务端执行认证、角色鉴权和数据归属校验。
- 私密内容必须在服务端完成权限过滤。
- 防止普通用户越权访问管理员功能。
- Markdown 内容需要进行安全处理，降低 XSS 风险。
- 拒绝 `javascript:` 等危险 URL 协议。
- 验证码具有有效期、错误次数和发送频率限制。
- 登录失败达到限制时提供临时防护。
- 禁用用户的登录凭证必须失效。
- 删除用户、删除内容等敏感操作必须校验权限。

### 7.3 可用性

- 用户能够清晰识别登录、注册、发布、编辑、删除等操作。
- 操作成功或失败后提供明确反馈。
- 删除操作提供二次确认。
- 搜索无结果时显示空状态及清除搜索条件的入口。
- 图片加载失败时显示占位提示。
- 表单校验错误应指出需要修正的内容。

### 7.4 兼容性

- 支持桌面端和手机浏览器。
- 具体浏览器版本范围待技术选型和测试阶段确定。
- 页面应适配不同屏幕尺寸。
- Markdown 正文应保持合理的可读性和布局。

### 7.5 可维护性

- 前端页面、业务功能和后台管理应具备清晰的职责边界。
- 认证、权限控制、内容管理等业务规则应便于维护。
- 数据库及接口设计需支持后续功能扩展。
- 具体模块划分和技术架构在设计文档中确定。

### 7.6 数据可靠性

- 成功保存的业务数据在服务重启后仍应保留。
- 需要明确数据库备份和恢复机制。
- 删除操作应严格遵守已确认的数据处理规则。
- 具体备份频率、保留周期和恢复目标待部署设计阶段确定。

### 7.7 无障碍要求

- 重要交互控件应具备清晰的名称和可识别状态。
- 表单错误信息不能只依赖颜色表达。
- 头像、社交链接图标等有意义的图片应提供适当的文本说明。
- 页面应具备基本的键盘操作能力。
- 具体无障碍标准及符合程度待 UI 设计与测试阶段进一步明确。

## 08 交互与界面要求

### 8.1 页面清单

| 页面     | 核心内容                   | 适用角色 |
| ------ | ---------------------- | ---- |
| 首页     | 个人介绍、随记统计、网站运行时间、社交链接  | 所有角色 |
| 随记列表   | 搜索、标签筛选、分页、随记摘要        | 所有角色 |
| 随记阅读弹窗 | Markdown 正文、标题目录、代码和图片 | 所有角色 |
| 片刻列表   | 动态展示、搜索、分页             | 所有角色 |
| 登录页    | 登录表单、找回密码入口            | 所有角色 |
| 注册页    | 昵称、邮箱、密码               | 所有角色 |
| 邮箱验证流程 | 验证码输入和验证结果             | 注册用户 |
| 找回密码页  | 邮箱验证码和密码重置             | 所有角色 |
| 个人资料页  | 资料修改、密码和邮箱管理、退出登录      | 登录用户 |
| 我的片刻页  | 个人动态列表及管理操作            | 登录用户 |
| 管理后台   | 随记、标签、片刻、用户和首页配置管理     | 管理员  |

### 8.2 页面跳转

主要页面流程如下：

```text
首页
├── 随记
│   ├── 随记列表
│   └── 阅读弹窗
├── 片刻
│   └── 片刻列表
├── 登录
│   ├── 注册
│   └── 找回密码
└── 用户头像菜单（登录后）
    ├── 个人资料
    ├── 我的片刻
    └── 管理后台（仅管理员）
        ├── 随记管理
        ├── 标签管理
        ├── 片刻管理
        ├── 用户管理
        └── 首页配置
```

### 8.3 导航交互

- 公共导航始终包含首页、随记和片刻。
- 未登录用户可以进入登录和注册页面。
- 登录后展示头像菜单。
- 头像菜单提供个人中心和退出登录。
- 管理员额外拥有管理后台入口。
- 不具备访问权限的用户不能通过隐藏菜单以外的入口访问受保护功能。

### 8.4 内容管理交互

- 随记点击后以弹窗阅读。
- 片刻正文按 Markdown 规则渲染。
- 创建和编辑表单在提交前执行必要校验。
- 删除操作必须显示二次确认。
- 取消确认不执行删除。
- 操作成功后，列表和相关统计及时更新。

### 8.5 搜索和分页交互

- 搜索提交后展示匹配结果。
- 随记支持关键词与标签组合筛选。
- 翻页时保留当前有效搜索和筛选条件。
- 清除条件后恢复默认列表。
- 删除当前页最后一条记录后，系统合理调整分页位置。
- 搜索无结果时展示空状态及清除条件入口。

### 8.6 关键界面状态

| 状态     | 交互要求                |
| ------ | ------------------- |
| 加载中    | 对需要等待的内容提供明确的加载反馈   |
| 空列表    | 显示暂无内容的提示           |
| 搜索无结果  | 显示无匹配结果，并提供清除条件入口   |
| 表单校验失败 | 指明需要修正的字段或内容        |
| 操作成功   | 显示成功反馈并更新相关页面数据     |
| 操作失败   | 显示可理解的错误信息          |
| 删除确认   | 明确提示删除对象及后果         |
| 图片加载失败 | 显示占位提示，不影响其他内容      |
| 无访问权限  | 拒绝访问，不展示受保护的数据      |
| 登录状态失效 | 提示重新登录，不允许继续执行受保护操作 |

### 8.7 原型图要求

本版本暂不附带最终 UI 原型图。

后续原型设计应至少覆盖：

1. 首页桌面端与移动端。
2. 随记列表及阅读弹窗。
3. 片刻列表及发布、编辑流程。
4. 登录、注册、邮箱验证和找回密码流程。
5. 个人资料与我的片刻。
6. 管理后台主要页面。
7. 删除确认、搜索无结果、加载失败和无权限等关键状态。

## 09 验收与发布要求

### 9.1 整体验收条件

第一版必须满足以下条件：

1. 首页能够展示博主个人介绍、随记数量、标签统计、网站运行时间及社交链接。
2. 所有用户均可以浏览随记，并使用搜索和标签筛选。
3. 随记阅读支持 Markdown、标题目录、代码高亮、代码复制和图片展示。
4. 普通用户不能管理随记和标签。
5. 注册用户能够完成邮箱验证、登录、找回密码和个人资料维护。
6. 普通用户能够管理自己的公开和私密片刻。
7. 私密片刻不会被无权用户通过搜索、URL 或接口访问。
8. 管理员能够管理随记、标签、所有片刻、用户及首页配置。
9. 禁用和删除用户时，系统正确执行账号状态和数据保留规则。
10. 所有永久删除操作均执行规定的确认与权限校验。
11. 服务端拒绝未经授权的管理操作。
12. 主要页面支持桌面端及手机浏览器。
13. 核心功能验收用例全部通过，且不存在阻断上线的严重缺陷。

### 9.2 上线标准

正式上线前应完成：

- 产品需求评审和需求基线确认。
- 规格说明书与技术设计评审。
- 核心功能测试和权限测试。
- 注册、登录、邮箱验证及密码重置测试。
- 私密片刻访问控制测试。
- 用户禁用、启用、删除和内容保留规则测试。
- Markdown 内容安全测试。
- 主要浏览器及移动端适配测试。
- 数据库备份和恢复方案确认。
- 生产配置及管理员账号初始化。
- 已知限制和未解决问题评估。

### 9.3 发布范围

第一版发布范围为本 PRD 中明确列出的全部核心功能。

未经评审确认的扩展功能不纳入本次发布范围。

### 9.4 已知限制

- 第一版不支持本地图片上传。
- 图片依赖外部 URL，无法保证外部图片长期可访问。
- 不支持片刻点赞、评论、草稿及用户关注等功能。
- 技术栈、部署方式及具体性能指标尚未确定。
- 具体 UI 原型、字段长度限制及验证码参数待后续阶段确认。

### 9.5 发布后检查

上线后应至少检查：

- 注册、登录及邮箱验证是否正常。
- 随记、片刻列表和搜索是否正常。
- 公开与私密内容的访问权限是否正确。
- 管理后台的权限限制是否生效。
- 用户禁用、启用及删除行为是否符合规则。
- 数据保存、备份和恢复机制是否正常。
- 页面在主要桌面端和移动端浏览器中的展示是否符合要求。
