## 4. V1.0 包含范围

- 首页个人介绍、内容统计、网站运行时间和社交链接。
- 随记列表、阅读、搜索、标签筛选及后台管理。
- 标签新增、编辑、删除及随记关联管理。
- 片刻发布、编辑、删除、公开或私密设置、搜索和分页。
- 注册、邮箱验证、登录、退出登录和找回密码。
- 个人资料、密码、邮箱及“我的片刻”管理。
- 用户列表、禁用、启用和删除。
- 管理后台及服务端权限控制。
- 通过 URL 展示头像、封面图和 Markdown 图片。

## 5. V1.0 不包含范围

- 片刻点赞和评论。
- 用户关注、私信等社交功能。
- 随记分类体系。
- 本地图片上传、托管和图片管理。
- 片刻草稿。
- 普通用户申请管理员角色。
- 第三方账号登录。
- 复杂内容推荐和个性化信息流。
- 原生移动端应用。

## 6. 非阻塞待确认事项

- 技术栈、API、认证机制和接口错误码。
- 详细字段长度、格式和搜索匹配规则。
- 验证码具体参数。
- Markdown 支持范围。
- 网站运行时间的展示格式。
- 用户列表字段和筛选条件。
- 浏览器兼容范围、性能指标、备份和恢复指标。
- 账号删除后的审计记录及数据保留周期。
- 完整原型和响应式布局。

上述事项若导致产品范围、角色权限、核心业务规则或验收标准发生变化，必须登记到《需求变更记录》并形成新的 PRD 版本。

## 7. 版本与变更规则

基线目录建立后不再直接修改。

- 仅澄清文字且不改变需求含义：形成 V1.0.x 草案并重新确认。
- 增加或调整 V1.x 范围内的需求：形成 V1.1、V1.2 等草案。
- 产品方向或核心范围发生明显变化：形成 V2.0 草案。

变更被接受后，应同步更新 PRD、SPEC、需求追踪矩阵、开发任务和测试记录，再建立新的基线目录。旧基线必须保留。
